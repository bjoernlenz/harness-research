# Trust Through Closeness vs Structure

## Essence

Some harnesses ask to be trusted because they stay close to familiar work surfaces. Others ask to be trusted because their structure is explicit.

## Representative Harnesses

- Aider
- Claude Code
- LangGraph
- PydanticAI
- OpenAI Agents SDK

## Primary Substrates Involved

- Repository / diff / terminal
- Graph / state
- Schemas / validation
- Handoffs / traces

## Trust Models Involved

- Repository closeness
- Permissioned agency
- Explicit control flow
- Schema validation
- Trace visibility

## Failure Modes Involved

- Review burden and context drift
- Permission fatigue
- Overengineering structure
- Validation churn
- Handoff mismatch

## Hidden Bets

- Closeness-side: familiarity and visible work surfaces create trust
- Structure-side: explicit state, types, and traces create trust

## What Each Side Sees Clearly

- Closeness-side sees trust as a lived working relationship
- Structure-side sees trust as an architectural property

## What Each Side Tends To Miss

- Closeness-side can under-specify system guarantees
- Structure-side can underestimate human friction

## Open Questions

- Which trust models scale best as tasks grow longer and more autonomous?
