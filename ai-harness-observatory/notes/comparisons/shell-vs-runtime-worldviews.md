# Shell vs Runtime Worldviews

## Essence

This is the contrast between systems that live inside familiar working environments and systems that want a dedicated runtime spine.

## Representative Harnesses

- Claude Code
- Pi
- OpenAI Agents SDK
- Semantic Kernel

## Primary Substrates Involved

- Terminal / shell / repository
- Agent objects / tools / traces
- Kernel / plugins / connectors

## Trust Models Involved

- Permissioned agency
- Minimal-core transparency
- Trace visibility
- Runtime composition

## Failure Modes Involved

- Context overreach
- Extension fragmentation
- Handoff mismatch
- Middleware heaviness

## Hidden Bets

- Shell-side: useful agency should compose with existing tools
- Runtime-side: durable systems need explicit orchestration and capability infrastructure

## What Each Side Sees Clearly

- Shell-side sees real work and composability
- Runtime-side sees scale, routing, and capability management

## What Each Side Tends To Miss

- Shell-side can underweight formal orchestration
- Runtime-side can drift away from tactile usefulness

## Open Questions

- When does shell intimacy become too sparse, and when does runtime infrastructure become too indirect?
