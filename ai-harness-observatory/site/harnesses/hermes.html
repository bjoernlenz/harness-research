Human Story

Hermes feels like it comes from impatience with disposable agents. Its public voice keeps repeating the same provocation: stop treating the agent like a one-session chatbot that forgets everything the moment the window closes. Let it remember. Let it write skills from experience. Let it live somewhere more durable than a tab.

That gives Hermes a different emotional shape from most coding harnesses in the observatory. It is not mainly trying to make code edits feel close to the repo. It is not mainly trying to make orchestration look explicit and elegant. It is trying to make the agent feel continuous. The same worker can meet you in the terminal, keep running through a gateway, answer on Telegram, spawn child agents, and come back with more memory than it had yesterday.

There is also a strong bodily story here. Hermes does not want one home. It wants many surfaces: CLI, messaging platforms, browser tools, plugins, MCP servers, multiple backends, cron, API mode. That could read as mere feature spread, but the deeper architectural claim seems to be that a useful agent should travel with its memory and habits instead of being trapped inside one interface.

So the human story is not just "more tools." It is a wager that agency becomes more real when it persists long enough to accumulate residue and procedures of its own. Hermes exists for people who want an agent that behaves less like a session and more like a continuing operational presence.

Hidden Bet

Long-lived agency becomes useful when memory and procedural learning compound across sessions.

Playfulness

The striking move is treating the agent like a long-lived worker that can remember, author its own skills, and keep operating across chat surfaces instead of resetting to a fresh persona each session.

Failure Modes

  • Configuration drift
  • Sandbox complexity
  • Tool-surface overload

What It Refuses

  • A stateless chat-only assistant
  • Tying the agent to one interface or one machine
  • Keeping learned procedures trapped inside a single session

Core Tension

Its strength is letting agency persist, learn, and spread across surfaces. Its tradeoff is that long-lived capability brings memory sprawl, platform complexity, and a wider trust surface to manage.

Relationships

  • Embodies Concept → Memory As Residue
    Hermes treats durable files, session history, agent-authored skills, and optional memory providers as accumulated residue rather than ephemeral chat context.
  • Embodies Concept → Sandboxed Agency
    Its multiple terminal backends and isolated execution surfaces make the bounded runtime part of the agent's practical body.
  • Externalizes Through → MCP As Tool Fabric
    Hermes grows outward by binding external MCP servers into its wider working body instead of limiting itself to one native tool surface.
  • Shares Hidden Bet With → OpenHands
    Both assume useful agency comes from giving the agent a richer practical body, though Hermes adds a stronger long-lived memory and learning story.
  • Different Complexity Center Than → Claude Code
    Hermes pushes complexity harder into persistent memory, skill curation, gateways, and backend choice, while Claude Code concentrates more on terminal composability and permissioned local workflows.
  • Competes For Same Use Case As → OpenHands
    Both target users who want a capable autonomous worker rather than a thin assistant, but Hermes frames that worker as a longer-lived multi-surface agent.
