Environment-Close vs Orchestration-Close vs Data-Close

Essence

The current corpus already forms a three-pole field: environment-close agency, orchestration-close agency, and data-close agency.

Representative Harnesses

  • Environment-close: Aider, Claude Code, Cursor, OpenHands, Pi
  • Orchestration-close: LangGraph, OpenAI Agents SDK, AutoGen, Semantic Kernel, PydanticAI
  • Data-close: LlamaIndex

Primary Substrates Involved

  • Repo / terminal / IDE / sandbox
  • Graph / handoffs / teams / kernels / schemas
  • Data / indexes / retrieval / workflows

Trust Models Involved

  • Closeness and supervision
  • Explicit structure and traces
  • Data grounding and retrieval relevance

Failure Modes Involved

  • Context or environment drift
  • Orchestration sprawl
  • Retrieval overload

Hidden Bets

  • Environment-close: usefulness lives near the work surface
  • Orchestration-close: reliability lives in explicit structure
  • Data-close: cognition is only as good as the knowledge substrate

What Each Side Sees Clearly

  • Environment-close sees practical embodied work
  • Orchestration-close sees system legibility
  • Data-close sees knowledge grounding

What Each Side Tends To Miss

  • Environment-close can under-specify deeper runtime structure
  • Orchestration-close can overvalue architecture before contact with work
  • Data-close can let retrieval dominate the whole design

Open Questions

  • Is this three-pole structure the real top-level taxonomy, or only a first-wave artifact?
